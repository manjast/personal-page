INCIDENT 01 — EVAL HARNESS PM-2026-001 / 02 / 06

Build the eval before the build.

PATTERN
A team builds a RAG system against 20–30 sample questions, picks a chunking strategy that "looks right," iterates on the prompt until the sample outputs read well, and ships.
FIX
Build the eval first. 50–100 questions from real users (not synthesized), graded 1–5 by the people who will use the system, run after every change. The eval answers one specific question: is the new system better than the old one, on the questions the users will ask?
3.1 → 3.7 on 80 questions
After one chunking change. Two pilots I worked on built the eval late, after 200+ users were in production. Both spent 3 weeks reverting prompt + chunking + retrieval changes that had been merged without measurement.

INCIDENT 02 — RETRIEVAL DIAGNOSTICS PM-2026-001 / 03 / 06

Trace retrieval on every failed answer.

PATTERN
When the system gives a wrong answer, the team rewrites the prompt. The system gives a different wrong answer. The team rewrites the prompt again.
FIX
Trace the retrieval first. For every failed answer, log the top-k chunks, similarity scores, source documents. The question is not "why did the model say this" — it is "did the retrieval find the right source, and did the model read it?"
2–3 weeks → 2–3 days
Prompt-engineering rabbit hole vs. the actual fix, once retrieval diagnostics were in place. One pilot: a chunker that had split a table across 2 chunks. 10-line change. No prompt change.

INCIDENT 03 — COST PER QUERY PM-2026-001 / 04 / 06

Log cost per query from day one.

PATTERN
The team builds a RAG system, ships to a small group, then a larger group, then is surprised when the monthly bill jumps 10x. The system is doing what it was told — top-k=20, 70B model, 500-token answer — but the cost per query is $0.15 and the team is running 50,000 queries a day.
FIX
Log per-query cost from day one. Every retrieval has a cost. Every LLM call has a cost. The first question after go-live: what is the cost per query, and who is the top-10% of users by cost?
4x cost cut
One configuration change. top-k=20 → top-k=5 + reranker. The team had been paying 4x more for worse answers. Reranker is more selective than dense retrieval: fewer chunks to process, better signal in the context window.

FINDINGS — 2026 COST DISCIPLINE PM-2026-001 / 05 / 06

The 2026 cost discipline.

Frontier model API prices look stable. They are subsidized by VC funding — the post-IPO price is widely expected to be higher than today's. Build the cost discipline now, while the pricing is in your favor.
FINDING 1 · MODEL
Open-weight alternatives — DeepSeek V4-Pro, GLM 5.2, Qwen 3.7 Max, Kimi K2.6, MiniMax M3 — ship at 10–30x lower cost than frontier closed-API. Deployable on the same major cloud providers (AWS Bedrock, Azure AI Foundry, Google Vertex, OCI). Deployment flexibility + pricing leverage + the option to self-host on dedicated infrastructure.
FINDING 2 · FORMAT
Toon cuts input tokens 30–40%, net +12% cost reduction in the best case. GCF goes further but adds reasoning cost. The net is format-dependent: pick per workload.
FINDING 3 · ARCHITECTURE
top-k=20 → top-k=5 + reranker cut cost 4x. Prompt caching reduces repeated-prefix cost 5–10x. The RAG-side lever is the cheapest one — 10-line chunker change, not a 10-week migration.
The era of "as much AI as you can" is over. The era of "as much AI as cost-justified" is here.
